# Local automatic Custom Maps

The generation order is music structure → actual musical targets → existing prey patterns → alternating L/R → interference → Satiety simulation → camera. All work stays local. Metadata is written last into `user://custom_maps/<MapId>/`; analysis.json records the selected targets, evidence, pulse alternatives, schedules and simulation results.

- Each phrase has exactly one Bite Target and one wave event. Targets come from measured band onsets; BPM grids never manufacture targets. Strong chord/melody, low-band and percussion attacks, phrase endings and structural impacts provide selection evidence. Band evidence does not claim isolated instrument transcription.
- Onset-based normalized tempo correlation and half/double-time alternatives are compared for alignment and readable four-pulse lead-ins. A weighted interval selection chooses strong payoffs over weaker conflicting earlier attacks. Camera and interference cannot edit these times.
- Pattern definitions are loaded from the existing patterns.csv. Dense percussion uses Small, regular/chord-driven material Medium, sparse/heavy passages Large. Matching compares the pattern's cue rhythm with preceding actual attacks. No new bite mechanic or multi-target phrase is introduced.
- Measured quiet sections remain sparse. Satiety uses the same SatietyDrainProfile as gameplay, including long foodless gap protection and outro behavior. Drain is searched using runtime gains, caps and miss penalties. All PERFECT and a representative 60% PERFECT / 25% GOOD / 10% BAD / 5% MISS sequence must both reach the existing clear threshold without starving first. This is a representative feasibility check, not a guarantee for every judgment ordering.
- Interference consumes structural changes and strong musical accents. The opening is clear; the middle uses one role at a time; later material escalates. A late structural climax may combine one pressure/fake-rhythm role with Sardine, at most two. Existing effect timing/duration definitions are reused. No random periodic schedule is generated.
- The separate v5 camera timeline uses WAVE_CLOSEUP, SHARK_CLOSEUP, PULLBACK, SIDE_PAN and SECTION_TRANSITION. Each shot has MOVE → HOLD → RETURN, with at least seven seconds between completed shots and subsequent starts. It is not a camera change per L/R prey. Strong sensory interference suppresses overlapping shots. No camera event changes judgment timing.
- MP3 title/artist/album/artwork extraction is preserved. Existing embedded art is used; missing art produces the title card, never fabricated artwork. Player maps and settings are never bundled with the export.

`game/debug/generator_quality_checks.tscn` verifies competing musical targets, a known-tempo acoustic fixture, a silent bridge, low-confidence structural events, immutable target timing, camera roles, runtime Satiety parity, generated gameplay and one Main Stage sibling. Its own generated test map is deleted in finally; existing player maps are untouched. Runtime launch proves data acceptance, not human listening approval or musical taste.
